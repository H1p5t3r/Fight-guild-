# Match, training and development menus

The native game opens at **Main menu**. Applied move data remains in memory when changing modes; **Save locally** in Development persists it across launches. Backing out of fighter selection discards draft selections and preserves an existing round.

| Entry | Sequence | Tools and exit paths |
| --- | --- | --- |
| Versus / Local versus | Main menu → Versus → Local versus → Side select → Fighter select → Loading → Intros → Opening → Match | Full-width arena; Esc/Start opens Resume, Restart scrum, Change fighters, Main menu. A completed match offers Rematch, Change fighters and Main menu. |
| Versus / Online versus | Main menu → Versus → Online versus → Local fighter select → Connection → Host or Join → Loading → Intros → Opening → Match | Opponent chooses their own fighter. Waiting exposes Cancel connection. Errors and disconnects return to the connection screen with the explanation and retained selection/address. Back cancels the connection and returns to fighter select, then Versus. |
| Training | Main menu → Training → Fighter and dummy select → Start training | Dummy behavior, starting Momentum, input history, hitboxes, pause, one-frame step and reset. No move editor. |
| Development | Main menu → Development → Fighter and dummy select → Open combat lab | Training tools plus move/buffer/Momentum editing, sprite review, import/export/save, unified gatling reference and rollback trial. The lab can also switch to local versus for testing. |

Local **Side select** uses left / neutral / right device cards. Each keyboard layout or controller can choose a side independently; both players need an assigned input to continue. Back discards unconfirmed assignments. Local Change fighters returns through the side screen, and Fighter select Back returns there. [Controls and side selection](input-controls.md) covers remapping, hot-plugging and keyboard swaps.

Fighter select has a central six-fighter grid. Choose **Player 1** or **Player 2** above it to edit that slot (Player 2 is the dummy in practice). Arrows/D-pad move through the two-column grid; focus previews and selects that fighter for the active slot. Up from the first row returns to the player selector; Down from the last row reaches Start. Both players may choose the same fighter, and both badges remain visible. Online selects only your local fighter.

Versus matches are **first to two Scrum wins**. The calls are **1st Scrum**, **2nd Scrum**, and **Final Down** at 1–1. A draw awards no win and replays the same call. Filled marks beside each health bar show wins. Between Scrums, a short score screen leads automatically into fresh health, Momentum, positions and a 99-second timer. The full results menu appears at 2–0 or 2–1. Local Rematch starts a new 0–0 match; Restart scrum preserves earlier wins while restarting the current Scrum.

Match entry loads the selected fighter resources, introduces both fighters, then delivers four beats: “The stands hunger for legends.” → “Let the guilds give them names.” → the current Scrum call → “Break the line!” Combat starts on the last call. Enter/A or Skip intros skips the character spotlights, preserving all four opening beats. Back cancels entry; a held selection confirm cannot skip the intro. Later Scrums and rematches omit repeated fighter spotlights. Training/Development use loading without the full ceremony, and practice Reset stays immediate.

Each selection has its own simplified-input toggle; motion inputs remain available. Versus starts with zero Momentum regardless of the practice reset setting. Training and Development retain their dummy and starting-meter preferences for the session. Development defaults to visible hitboxes; Training and matches default to sprites without collision overlays.

Navigation supports mouse, arrows/Tab/Enter, and the controller D-pad/A. Esc/B goes back in menus. Esc/Start opens or closes the in-match menu. Home ignores Back; quitting is an explicit button. Focus moves to an enabled control on every menu entry. A held confirm or movement input must be released before combat accepts input after entry/resume.

Menu pages use interruptible 840 ms eased entrances and 540 ms exits; incoming navigation responds immediately. Outgoing controls cannot receive focus or clicks. Layer changes crossfade in 840 ms, and fighter portraits reveal over 780 ms. Each fighter intro lasts 3.5 seconds; the opening phrases hold for 3 seconds each, the Scrum call for 1.8 seconds, and the release call for 1.65 seconds. Score intermissions last 3.5 seconds. New fights hold the combat clock at zero throughout loading, intros and the opening. The home footer has a persistent **Motion: Full / Reduced** preference; reduced motion uses fades of at most 90 ms without translation while retaining ceremony reading time. These timings affect presentation only.

Offline combat freezes during match transitions, while outside the play screen or while a modal dialog is open. Resume preserves the exact round, including a lab frame-step pause. A fighter-change cancellation returns to its originating screen and does not reset the round. Training/Development retain the manual Reset workflow when their round ends.

Online combat **continues with neutral local input** while its menu is open. Its menu explicitly says so and offers Resume or Leave match & main menu. A local restart or fighter change is unavailable during the connection. Scrum wins are recorded only from a fully confirmed rollback state. Both players must finish the intermission, preparation and opening before the next Scrum starts. At the end of the first-to-two match, the results screen offers Return to online lobby; both players host/join again for another match. Negotiated rematches, matchmaking and reconnect remain backlog items.

`match_entry_verification.gd` checks actual resource preparation, both intros, four-beat order, skip/cancel, held-input isolation, 2–0 and 2–1 results, draw replay and ENet readiness/generation isolation. `GameMenus` presents the pages and emits actions; `main.gd` owns transitions and simulation scheduling. `transition_verification.gd` exercises running transitions, rapid interruption, held-input isolation and reduced motion. `menu_verification.gd` exercises these paths in both the editable project and release package, including actual loopback ENet handshake/cancel/disconnect, keyboard and synthetic-controller navigation. Physical controller and Windows hardware testing remain separate.

Presentation follows the [Guild Ball menu style](menu-style.md). Headings and navigation stay fixed while bodies scroll. Controls has separate Player 1, Player 2 and Gamepad reference tabs and restores focus on close.
